Proposed replacement for AGENTS.md Footage retention write-API guidance, for Mech to file separately. AGENTS.md and other protected guidance files are unchanged in this branch.

Retention reads follow AUTH_ENABLED. Retention settings PUT, manual-run POST, and clip-protect POST always require MutationGuard CSRF/origin checks plus a direct loopback or RFC1918 client. AUTH_ENABLED=true additionally requires a valid JWT; AUTH_ENABLED=false permits these writes without a token. Keep SetTrustedProxies(nil): X-Forwarded-For and X-Real-IP must not authorize writes. CGNAT and IPv6 ULA are not RFC1918 and remain rejected. Preserve existing Origin/Referer validation and CSRF-header requirements; do not widen forwarded-protocol trust. Malformed dry_run returns 400; unknown RETENTION_DRY_RUN keeps dry-run on.

Settings GET preserves flat config fields and adds status.last_run, status.next_run, and status.last_dry_run. next_run is an estimate, not a scheduler deadline. Settings PUT accepts config fields only and ignores footage_path; do not round-trip the GET status field into PUT. Run summaries persist separately in CONFIG_PATH/retention-status.json. Storage GET counts logical regular-file bytes by Tesla directory and whole-filesystem used/free bytes. Verify with backend/api/retention_http_test.go, retention_ui_test.go, retention_auth_test.go, and backend/services/retention_status_test.go using fixture footage only.
